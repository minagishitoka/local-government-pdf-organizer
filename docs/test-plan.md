# テスト計画

## 基本テスト

- 1ページPDF
- 999ページPDF
- 1000ページPDF
- 1001ページPDF
- 150MB付近のPDF
- 日本語ファイル名
- 同名タイトルの複数資料
- 暗号化PDF
- 空PDF
- 開けない/破損PDF

## PDF結合テスト

- 原本順序と結合順序の照合
- 原本ページ数と結合後ページ範囲の照合
- 対応表が複数ページになるケース
- しおり件数と資料件数の一致
- しおりタイトルと遷移先の一致
- 結合後PDFの再読込検証
- 途中ページ破損PDF
- 結合失敗時に未完成PDFを残さないこと

## AIタイトルテスト

- 1ページ目が「目次」の議事録
- 冒頭3ページを見ても正式タイトルが分からない資料
- AIが元ファイル名を返すケース
- AIが長すぎるタイトルを返すケース
- AI応答が空/不正JSONのケース
- API 429/500系一時エラー

## ファイル名テスト

- `資料.pdf` が1件
- `資料.pdf` が同一巻に複数件
- AIタイトルと元ファイル名が同じケース
- Windowsパス長に近いタイトル

特に同名衝突時に `資料.pdf_2.pdf` のような二重拡張子が発生しないことを確認する。

## TXT→Wordテスト

- 全資料がWordへ入ること
- 資料番号・順序・タイトルが対応表と一致すること
- PDF PAGEとORIGINAL PDF PAGEが保持されること
- TXT途中切断を検知すること
- TXT中に `【資料 001】` を本文として含めた場合の境界衝突
- `[PDF PAGE 123]` を本文として含めた場合の境界衝突
- 文字抽出空ページがある場合に `needs_review` になること
- スキャンPDFで大量に文字抽出が空になるケース

## 再開テスト

- 処理途中で強制終了
- state.jsonからの再開
- 既存の結合PDF/TXT/Wordが二重生成されないこと
- 元PDFを差し替えた場合にrecord_keyで再処理されること
