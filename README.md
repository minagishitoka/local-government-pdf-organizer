# local-government-pdf-organizer

自治体議会資料のPDFを、研究・AI解析に耐える形へ整理するためのPythonツールです。

## 目的

大量の自治体議会資料PDFについて、次の処理を一連で行います。

1. PDFを検査する
2. Geminiで資料冒頭から正式タイトルを取得する
3. AIタイトルを機械的に検証する
4. 原本を変更せず、整理済みコピーを作る
5. 1000ページ・150MBを目安にPDFを結合する
6. 原本と結合後ページの対応表をPDF先頭に付ける
7. 結合PDFをTXTへ変換する
8. TXTだけを入力としてWordを生成する
9. CSV・state.jsonで処理状況と対応関係を記録する

## なぜPDFをTXT・Wordにするのか

TXT/Word化は単なる書式変換ではありません。

大量の議会資料をClaude等のAIへ投入する際、PDFにはページ数や視覚解析に関する形式固有の制約があります。そのため、文字情報を持つPDFについては、まずPython（PyMuPDF）で文字を抽出し、AI投入用のテキスト資料へ変換します。

Wordは最終的な閲覧資料というより、資料境界・見出し・PDFページ番号を保持したAI解析用コンテナとして扱います。

なお、画像だけのスキャンPDFでは文字抽出できない場合があります。その場合は抽出失敗を隠さず要確認として残し、原PDFを別途確認する方針です。

## 基本設計

```text
原PDF
  ↓
機械検査
  ↓
Geminiによるタイトル候補取得（冒頭3ページ）
  ↓
AI出力検証
  ↓
原本を保護したリネームコピー
  ↓
対応表作成
  ↓
PDF結合（1000ページ・150MB上限）
  ↓
結合PDF検証
  ↓
PDF → TXT
  ↓
TXT → Word
  ↓
Claude / Gemini等で研究・解析
```

## 安全方針

- 原本PDFは変更しない
- 異常PDFを黙ってスキップしない
- AIのタイトルを無条件に信用しない
- AIタイトルが怪しい場合は元ファイル名へフォールバックし、要確認にする
- 結合前後でページ数・しおり・遷移先を検証する
- TXT/Word工程でも資料欠落を検知する
- state.jsonで途中状態を保存し、再実行可能にする

## 必要なライブラリ

```bash
pip install pypdf reportlab google-genai pymupdf python-docx
```

## APIキー

Gemini APIキーはリポジトリへ絶対に登録しないでください。ローカルの設定欄にのみ設定してください。

## 査読

2026-09-16時点で、GeminiとClaudeに独立したコードレビューを依頼しました。両者とも「軽微な修正後に実用投入可能」と評価し、異なる観点から問題を発見しました。

- Gemini: API 429耐性、TXT→Word境界文字列衝突などを指摘
- Claude: 同名ファイル衝突時の `.pdf.pdf` 再発バグ、TXT→Word資料欠落検知不足を指摘

これらは開発履歴とテスト計画に記録します。
